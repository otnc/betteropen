# Contributing

Thanks for your interest in improving betteropen!
This guide gets you set up and explains how the project is put together.
If anything here is unclear, opening an issue to ask is welcome.

## Getting set up

You'll need Node.js >= 20.
Then install the dependencies:

```sh
npm install
```

Commit the lockfile generated by your package manager (`npm`).

## Scripts

| Command | What it does |
| --- | --- |
| `npm run build` | Bundle ESM/CJS + type declarations with tsup |
| `npm run test` | Run the tests once with vitest (`npm run test:watch` to keep them running) |
| `npm run test:coverage` | Run the tests with a coverage report |
| `npm run typecheck` | Type-check with `tsc --noEmit` |
| `npm run format` | Format the code, writing the fixes (Biome) |
| `npm run format:check` | Check formatting without writing (Biome) |
| `npm run lint` | Lint the code without writing fixes (Biome) |
| `npm run lint:fix` | Lint the code, writing the fixes (Biome) |
| `npm run check` | Lint, format and organize imports, writing the fixes (Biome) |
| `npm run ci` | The same checks without writing — what CI runs |

Before opening a pull request, make sure the full set passes:

```sh
npm run ci && npm run typecheck && npm run test && npm run build
```

## Conventions

- **Formatting and linting is Biome** (`biome.json`) — single quotes, no semicolons, trailing commas, 100-column width.
  Running `npm run check` before you commit handles all of it.
- **Tests live next to the code** as `*.test.ts` and run with vitest.
- **Comments and docs are in English** and kept brief.
- **Type-only imports use `import type`** (`verbatimModuleSyntax` is on).
- **OS integration has no dependencies.** Default browser detection, PowerShell/WSL handling, and similar platform code is implemented directly on top of Node built-ins and system commands rather than third-party packages. The library itself (`src/index.ts` and everything it imports) has zero runtime dependencies; only the CLI adds two, both used solely by `src/cli.ts` — `citty` for flag parsing and `magic-bytes.js` for stdin type detection.

## Pull requests

Keep each change focused and add tests for any new behaviour.

## Releasing (maintainers)

Releasing is one manual step.
From the Actions tab, run the `release` workflow (`workflow_dispatch`) and give it a `version` input — either a bump keyword (`patch` / `minor` / `major` / `prerelease`) or an explicit version like `0.1.0`.
The workflow runs the checks and build, bumps `package.json`, publishes to npm with provenance via **trusted publishing** (OIDC — no `NPM_TOKEN` needed), pushes the version commit and tag, and creates a GitHub Release with generated notes.

Trusted publishing must be configured once on npmjs.com:
package **Settings → Publishing access → Trusted publishers → GitHub**, pointing at this repository's `release.yml` workflow.
